### 双指针

> 快慢指针如下.

很通常地, 我们在处理一个数组或者是链表的时候, 喜欢再开辟一个新的存储空间来保存新的处理完的内容, 或者是对原数组进行删除操作. 前者在空间复杂度上不好, 后者在时间复杂度上不好.

快慢指针践行了"删除即为覆盖"的思想. 在时间和空间复杂度上都很友好.

- 快指针: 扫描指针, 先去获得符合要求的元素;
- 慢指针: 插入指针, 将快指针得到的元素插入.

这只是双指针的一个典型的示例. 有很多题目可以考虑使用双指针切入, 不一定要是快慢, 比如你也可以说二分法是一种双指针...

**一个medium难度的双指针题目:**

**description**: 返回一个存在环路的链表中环路开始的位置.

Given a linked list, return the node where the cycle begins. If there is no cycle, return `null`. To represent a cycle in the given linked list, we use an integer `pos` which represents the position (0-indexed) in the linked list where tail connects to. If `pos` is `-1`, then there is no cycle in the linked list. Do not modify the linked list.

**example**:

```text
Input: head = [3,2,0,-4], pos = 1
Output: tail connects to node index 1
Explanation: There is a cycle in the linked list, where tail connects to the second node.
```

**Thoughts**:

一开始我想要使用模拟遍历的方法来解决这个问题.但是发现去判断一个完整的环路使用遍历的方式不太合适.然后用双指针的方法试了一试,发现没有结论不够直观,也就是没有办法直接通过两个指针快慢遍历来解决这个问题.

**Solution**:

> 实际上使用的就是快慢指针,不过不是用于编码,而是用于数学分析.最后使用双指针来完成编码.

考虑一个带环的链表, head为x, 环中一个checkpoint为z, 所求的环路开始的位置为y. 设

d(x,y) = a, d(y,z) = b, d(z,y) = c(因为环路的存在).

<img src="https://blog-1340370041.cos.ap-nanjing.myqcloud.com/oss/map.png" width="50%">

假设一组快慢指针, fast指针速度是slow指针的`c`倍.

当slow指针与fast指针在z相遇时(更确切的应该叫追及), slow指针行走距离是`a+b`;fast指针行走距离时`a+n(b+c)+b`.有等式:

$$ c(a+b) = a+b + n(b+c) $$ 变形得

$$ (c-1)a = (n+1-c)b +(n-c)c $$ 即

$$ a = [(n+1-c)/(c-1)]b + [(n-c)/(c-1)]c $$

取c=2,得

$$ a = (n-1)b + nc $$

那么可以知道,如果再假设一组双指针,速度是一致的(某个符合条件的常数),一个指针从x出发,一个指针从z出发,那么两个指针运动之后一定会在y点相遇, 而y即为题目所求之答案.

### 滑动窗口

> 考虑一种情形， 让你寻找符合条件的子序列. 
>
> 注意到子序列都应该是原序列中连续的一段, 所以用类似于滑动窗口一样的两个指针"框选"出结果显得尤为合理.

编码的一些注意要点:

滑动结束窗口就是遍历这个序列的一个指针.

滑动开始窗口一开始在序列起始位置, 根据滑动的要求在上面那个指针的for循环里更新(就是向前滑.)

时间复杂度O(n).

### 哈希表

[1. 两数之和 - 力扣（LeetCode）](https://leetcode.cn/problems/two-sum/solutions/434597/liang-shu-zhi-he-by-leetcode-solution/?envType=study-plan-v2&envId=top-100-liked)

LeetCode第一题,绝对经典的题目.哈希表的解法可以降低一个量级的时间复杂度. 用`O(1)`的时间找出`x`对应的`target-x`的索引.

我们创建一个哈希表，对于每一个 `x`，我们首先查询哈希表中是否存在 `target - x`，然后将 `x` 插入到哈希表中，即可保证不会让 `x` 和自己匹配。

```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        unordered_map<int, int> hashtable;
        for (int i = 0; i < nums.size(); ++i) {
            auto it = hashtable.find(target - nums[i]);
            if (it != hashtable.end()) {
                return {it->second, i};
            }
            hashtable[nums[i]] = i;
        }
        return {};
    }
};
```
